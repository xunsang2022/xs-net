# 消息注册与消息处理流程

> 涉及模块：`xs-net-message`、`xs-net-core`、`game-message-action`、`game-node-gateway` 和 `game-node-modules`。

## 核心概念

| 名称 | 含义 |
|---|---|
| `RpcMessageSpec` | 单条协议契约：协议号、Protobuf 类型、解析器、DTO 编解码、目标角色和路由要求 |
| `RpcMessageRegistry` | 根据 `rpcNum`、Protobuf 类型或 DTO 类型查询协议契约 |
| `RpcMessageRegistryBuilder` | 构建不可变注册表，并阻止重复协议号、Protobuf 类型或 DTO 类型 |
| `NetMessage` | Protobuf 信封，包含 `rpcNum` 和 `data` |
| `RpcMessage` | 可跨节点路由的 RPC 消息抽象 |
| `channelId` | JWT 的 `cid` claim；Gateway 下行路由和 `ChannelActor` 实体 ID |

## Gateway wire protocol

Gateway 的 Netty TCP 协议为：

```text
len (4B, big-endian, 表示后续 NetMessage 字节数) | NetMessage protobuf bytes
                                                   ├─ rpcNum
                                                   └─ data
```

首帧例外：它同样带 4 字节长度前缀，但消息体是 UTF-8 JWT 文本。认证完成后才解析 `NetMessage`。

`rpcNum` 和 payload 都位于 `NetMessage` 内，Gateway 帧不存在额外的 `rpcNum` 或 `errorCode` 头。`MessageAble` 的跨节点转换不等同于 Gateway 的 Netty wire protocol；客户端必须以 `NettyFramer` 的长度前缀格式实现收发。

## 注册与节点装配

1. `game-message-action` 定义 Protobuf、DTO、路由角色接口和 `GameRpcMessages` 协议表。
2. `GameRpcMessages` 以 `RpcMessageSpec` 描述每个 `rpcNum` 对应的 Protobuf parser、DTO codec、方向、可见性和目标角色。
3. 节点启动时初始化 `RpcMessageRegistry` 与 `MessageAble`。
4. `NodeActor` 扫描当前节点配置的 Actor 包；拥有该角色的节点初始化本地 Cluster Sharding 实体。
5. 对于当前节点不拥有的协议角色，节点初始化代理分片，使 Akka 可将消息路由至远端拥有该角色的节点。

```text
GameRpcMessages / RpcMessageRegistry
                ↓
        MessageAble.initialize
                ↓
 NodeActor 扫描 Actor 和节点 roles
                ↓
  本地角色 → 初始化实体分片
  远端角色 → 初始化代理分片
```

## 上行：客户端到 Logic

1. 客户端向 Gateway 建立 TCP 连接，首帧提交 JWT。
2. `AuthHandler` 校验 JWT，读取 `cid` 并注册 `channelId → Netty Channel`。
3. 后续帧经长度解码后解析为 `NetMessage`。
4. Gateway 使用 `rpcNum` 查询 `GameRpcMessages`，解析 `data` 并通过协议 codec 还原 DTO。
5. Gateway 从 DTO 提取 `playerId`，并投递到 `PlayerMessage` 的分片实体。
6. 若协议未知、payload 无法解析或没有 `playerId`，Gateway 记录失败；解析异常会关闭该连接。

## 下行：Logic 到客户端

1. Logic 的 `PlayerActor` 产生 S2C 消息。
2. `AkkaKit.tell` 按 `channelId` 将消息投递给 Gateway 的 `ChannelActor` 分片。
3. `ChannelActor` 从 `ChannelRegistry` 获取活跃 Netty Channel。
4. 消息转换为 `NetMessage`，`NettyFramer` 增加 4 字节大端长度前缀，再写回客户端。
5. Channel 不存在或失效时，消息不会重连客户端；调用方应按业务需要处理离线状态。

## 本地与远端分片

`AkkaKit` 为本地角色直接投递 Java 对象。对于不在当前节点的角色，它将可路由消息转换为 `NetMessage` 后交由 Akka Cluster 传输。因而：

- 同一协议必须在注册表中有唯一契约；
- 跨节点消息必须可转换为 `NetMessage`；
- 角色接口、Actor 扫描路径和 Akka 节点 roles 必须一致；
- Gateway 的 TCP 帧格式只用于客户端与 Gateway，不应与 Akka 跨节点消息格式混用。

## 相关源码

- `xs-net/xs-net-message/.../RpcMessageSpec.java`：协议契约字段与校验；
- `xs-net/xs-net-message/.../RpcMessageRegistryBuilder.java`：注册表构建与去重；
- `xs-net/xs-net-message/.../MessageAble.java`：DTO、`RpcMessage` 和 `NetMessage` 转换；

- `game-server/game-node-gateway/.../NettyFramer.java`：Gateway 长度前缀编码；
- `game-server/game-node-gateway/.../AuthHandler.java`：JWT 握手和上行消息路由。
